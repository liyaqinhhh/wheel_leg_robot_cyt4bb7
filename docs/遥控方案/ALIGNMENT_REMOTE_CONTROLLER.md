# ALIGNMENT — 遥控器功能开发

## 1. 原始需求摘要

在工程原有基础上编写遥控器功能，使轮腿机器人可通过无线串口/BLE模块进行实时遥控操控。

## 2. 需求确认

### 硬件方案
- **通信接口**: UART_1（P04_0/P04_1），共用无线透传模块接口
- **波特率**: 115200
- **原因**: PCB 仅引出 UART_1 和 UART_2，UART_2 已被电机驱动占用
- **物理互斥**: 无线串口模块和遥控器无线模块**不会同时接入**，插哪个就是哪个模式
  - 插无线串口模块 → 遥测模式（发送 $T/$I 数据）
  - 插遥控器无线模块 → 遥控模式（接收控制帧）
- **软件策略**: 始终监听 UART_1 接收数据，根据帧头自动识别
  - 收到 0x5A 开头的帧 → 遥控控制帧，进入遥控处理
  - 收到 'P' 开头的行 → AI调参命令，进入PID调参处理
  - 遥测发送始终运行（只是遥控器接入时无人接收，无影响）

### 遥控协议设计（二进制帧）

```
帧格式: [0x5A] [len] [type] [data...] [checksum]
```

| 字段 | 长度 | 说明 |
|------|------|------|
| Header | 1B | 0x5A（区别于遥测的 '$'=0x24） |
| Length | 1B | 帧总长度（含 header 和 checksum） |
| Type | 1B | 命令类型 |
| Data | 变长 | 命令数据 |
| Checksum | 1B | 前面所有字节的 XOR |

**命令类型定义**:

| Type | 名称 | Data 长度 | Data 内容 |
|------|------|----------|----------|
| 0x01 | 摇杆数据 | 8B | 4×int16: joystick[0~3] |
| 0x02 | 模式切换 | 1B | turn_mode 值 (0/2/3/6) |
| 0x03 | 高度调节 | 1B | 0=保持, 1=增高, 2=降低 |
| 0x04 | 急停控制 | 1B | 1=急停, 0=恢复 |
| 0x05 | 心跳包 | 0B | 无数据，仅维持连接 |

**摇杆帧示例** (12字节):
```
[0x5A] [0x0C] [0x01] [j0_H][j0_L][j1_H][j1_L][j2_H][j2_L][j3_H][j3_L] [chk]
```

### 控制功能（4项）

| # | 功能 | 输入映射 | 控制输出 | 优先级 |
|---|------|---------|---------|--------|
| F1 | 前后速度+左右转向 | joystick[1]→速度, joystick[2]→转向 | Yao.Target_Speed, Deviation_Value | P0 必须 |
| F2 | 模式切换 | type=0x02, data=turn_mode | turn_mode (0/2/3/6) | P1 重要 |
| F3 | 高度调节 | type=0x03, data=方向 | Yao.Target_height | P2 增强 |
| F4 | 急停功能 | type=0x04, data=1/0 | flag_stop | P0 必须 |

### 发送端（PCB遥控器）
- **PCB遥控器**: 用户自制的PCB遥控器，内置无线透传模块，与机器人端无线模块配对
- **Python 上位机**: 通过无线串口发送控制帧（可提供示例脚本，用于调试）

## 4. 关键约束与风险

| # | 约束/风险 | 影响 | 缓解措施 |
|---|----------|------|---------|
| C1 | UART_1 物理互斥（遥测/遥控不同时接入） | 无冲突 | 无需模式切换，软件自动识别帧类型 |
| C2 | 遥控信号丢失安全 | 机器人失控 | 500ms超时→自动停车(flag_stop=1) |
| C3 | 速度环当前设定值为0 | 遥控速度需接入速度环 | 修改16ms中断中速度环设定值来源 |
| C4 | yaokong_data_deal() 有bug | 双return语句 | 修复并扩展该函数 |
| C5 | 二进制帧与ASCII遥测帧共存 | 解析冲突 | 0x5A header 区别于 '$'=0x24 |
| C6 | 主循环硬编码零输出 | 遥控信号无法生效 | 移除硬编码，改为遥控驱动 |
| C7 | AI调参功能也用UART_1接收 | 功能冲突 | 物理互斥：插遥控器无线模块时AI调参不工作，反之亦然；软件按帧头区分(0x5A vs 'P') |
| C8 | BLE6A20 传输延迟 | 控制响应慢 | BLE 115200波特率足够，延迟<50ms |

## 6. 验收标准

1. 无线模块通信正常，UART_1 收发无误
2. 插入遥控器无线模块后，收到遥控帧自动处理，无需手动切换
3. 摇杆推杆→机器人前后移动+左右转向，响应平滑
4. 模式切换命令→turn_mode 正确切换
5. 高度调节命令→腿高变化可感知
6. 急停命令→机器人立即停车
7. 遥控信号丢失超过 500ms→自动停车
8. 松开摇杆→速度/转向自动归零
9. 遥测发送始终运行（遥控器接入时无人接收，无影响）
10. 提供 Python 上位机示例脚本
