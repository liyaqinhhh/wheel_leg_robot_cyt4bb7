# GPS 航向校准方法（扩展功能）

> 本文档记录各种航向校准方案，作为未来扩展参考。当前阶段采用"开机停在第一个航点"的约束进行校准。

## 1. 问题背景

GPS 导航的核心问题是：**如何确定机器人当前朝向？**

- GPS 只能提供位置（经纬度），不能直接提供朝向
- IMU 的陀螺仪可以积分得到航向，但存在漂移
- 两者需要校准/融合才能得到准确的航向

当前方案（约束法）：**开机时机器人必须停在第一个航点，面朝下一个航点方向**，此时：
- GPS 方位角 = 从当前点到下一航点的方位角（已知）
- IMU yaw = 当前陀螺仪积分值
- 偏移量 = GPS方位角 - IMU_yaw

## 3. 方法详解

### A. 起点约束法（当前方案）

**原理**：开机时人工将机器人对准第一个航段方向，记录 IMU-GPS 偏移量。

**操作流程**：
1. 开机，等待 GPS 定位
2. 将机器人搬到第一个航点
3. 人工将机器人面朝第二个航点方向
4. 按键确认校准
5. 系统记录 `offset = GPS_target_bearing - IMU_yaw`

**优点**：零硬件成本，实现简单
**缺点**：每次开机需要人工操作，依赖操作者方向感

---

### B. 双天线 GPS 航向

**原理**：两根 GPS 天线安装在机器人上（间距 ≥ 20cm），通过载波相位差分直接计算天线基线方向，得到精确航向。

**硬件**：
- TAU1201/GN42A 本身支持双天线（THS 语句输出航向）
- 需要第二根有源天线 + 分线器
- 天线间距越大精度越高（20cm → ~1°，1m → ~0.1°）

**代码**：项目中已有 `gps_gnths_parse()` 解析 THS 语句：
```c
// THS 语句格式：$GNTHS,hhmmss.ss,heading,T,mode*checksum
// heading 即为双天线航向角
gnss.antenna_direction  // 已有字段，单位度
```

**优点**：绝对航向，无漂移，精度高
**缺点**：需要额外天线硬件，天线安装有要求

---

### C. 运动方向法（GPS 速度方向）

**原理**：当机器人以一定速度（> 0.5m/s）直线行驶时，GPS 速度方向 ≈ 机器人朝向。

**数据来源**：RMC 语句中的 `direction` 字段：
```c
gnss.direction  // GPS 速度方向，单位度，[0,360)
```

**校准时机**：
1. 开机后先让机器人直线行驶 2~3 秒
2. 读取 `gnss.direction` 作为真值
3. 计算偏移量 `offset = gnss.direction - IMU_yaw`

**优点**：无需额外硬件，无需停在特定位置
**缺点**：
- 需要开阔场地（多径效应会干扰方向）
- 低速时方向不稳定
- 转弯时方向不准确
- 首次需要人工启动直线行驶

---

### D. 多点对齐法

**原理**：如果路线已知（航点已存储），机器人行驶到第一个航点后，系统自动根据"当前位置→下一航点"的方位角校准。

**流程**：
1. 开机，GPS 定位
2. 机器人行驶到最近的已知航点
3. 系统自动计算 `bearing = get_two_points_azimuth(当前, 下一航点)`
4. 当机器人开始朝下一航点移动时，用运动方向验证
5. 校准完成

**优点**：半自动，不需要精确停在起点
**缺点**：需要先到达一个已知航点，初始阶段仍有不确定性

---

### E. 磁力计融合

**原理**：9 轴 IMU（imu963ra）内置磁力计，可测量地磁场方向得到绝对航向。

**硬件**：项目已有 imu963ra（9 轴），磁力计数据可用。

**融合方案**：
```
航向 = α × 磁力计航向 + (1-α) × 陀螺仪积分航向
```

**优点**：绝对参考，无累积漂移
**缺点**：
- 受铁磁干扰严重（电机、钢结构附近不可用）
- 需要磁力计校准（椭球拟合）
- 室内外磁场差异大
- 实现复杂度高

---

### F. RTK 绝对定位

**原理**：使用 RTK（Real-Time Kinematic）差分 GPS，定位精度可达厘米级，航向精度可达 0.1°。

**硬件**：需要 RTK 基站 + 移动站，或 NTRIP 网络差分服务。

**优点**：最高精度
**缺点**：成本高，需要基站或网络，实现复杂

---

## 4. 推荐演进路线

```
当前阶段 ──→ 短期 ──→ 中期 ──→ 长期
   │            │         │         │
   ▼            ▼         ▼         ▼
 起点约束法   运动方向法  双天线GPS   RTK
 (已确定)    (零成本升级) (硬件升级) (专业级)
```

### 短期升级：运动方向法

在起点约束法基础上，增加"行驶校准"模式：
1. 开机后先直线行驶 2 秒
2. 用 `gnss.direction` 自动校准 IMU 偏移
3. 校准完成后进入导航模式

这是**零硬件成本**的升级，只需软件修改。

### 中期升级：双天线

TAU1201/GN42A 已支持双天线，只需加装第二天线：
1. 解析 THS 语句获取 `gnss.antenna_direction`
2. 用双天线航向替代 IMU 积分
3. IMU 仅用于短期插值（GPS 10Hz → IMU 1kHz 之间插值）

## 5. 校准数据存储

无论哪种校准方法，校准结果都应存入 Flash，避免每次开机重新校准：

```c
// 存储在 Flash 页 51 的元数据中
typedef struct {
    float imu_gps_yaw_offset;    // IMU-GPS 航向偏移量（度）
    float calibration_radius;    // 到达判定半径（米）
    uint32 calibration_method;   // 校准方法标识
    uint32 calibration_time;     // 校准时间戳
} GpsCalibrationData;
```

> 注意：IMU 零偏每次开机可能不同，`imu_gps_yaw_offset` 建议每次开机重新校准，不依赖 Flash 中的旧值。
