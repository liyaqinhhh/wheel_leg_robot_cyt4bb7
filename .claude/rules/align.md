# 6A 工作流执行规则（项目级强制规范）

你必须严格按照以下 6A 阶段顺序执行任何开发任务，禁止跳过任何阶段。每个阶段完成后必须生成对应文档，并在下一个阶段开始前等待人工审查（Approve）。

## 阶段 1: Align（对齐阶段）
**目标**：模糊需求 → 精确规范，彻底消除歧义。

**执行步骤**：
1. 分析项目上下文：现有结构、技术栈、架构、依赖、代码风格、业务域。
2. 创建文档：`docx/任务名/ALIGNMENT_[任务名].md`
   - 包含原始需求总结、边界确认、现有项目理解、疑问澄清清单。
3. 智能识别歧义，生成结构化问题清单（优先级排序）。
4. 主动中断询问关键决策点（尤其是涉及业务逻辑、优先级、技术约束时）。
5. 基于用户反馈更新理解，最终生成 `docs/任务名/CONSENSUS_[任务名].md`，包含：
   - 明确的需求描述
   - 具体、可测试的验收标准（推荐使用 Given-When-Then）
   - 技术约束、集成方案
   - 所有假设与边界已确认

**质量门禁**：
- 需求无歧义，边界清晰
- 验收标准具体可验证
- 所有关键假设已得到确认或记录
- 用户或人工确认对齐完成后再进入下一阶段

## 阶段 2: Architect（架构阶段）
**目标**：共识文档 → 系统架构设计，先画图纸再动工。

**执行步骤**：
1. 基于 CONSENSUS 和 ALIGNMENT 文档进行设计。
2. 生成 `docs/任务名/ARCHITECTURE_[任务名].md`，必须包含：
   - 整体架构图（用 Mermaid 绘制）
   - 分层/模块设计、核心组件
   - 接口契约定义（API 规格）
   - 数据流向图、模块依赖关系
   - 异常处理、安全策略
3. 严格复用现有组件，避免过度设计，确保与现有架构一致。

**质量门禁**：
- 架构清晰、可行
- 接口定义完整
- 与现有系统无冲突
- 用户审查批准后才能进入原子化拆分

## 阶段 3: Atomize（原子化阶段）
**目标**：大任务 → 可独立执行的小原子任务。

**执行步骤**：
1. 基于 DESIGN 文档生成 `docs/任务名/TASKS_[任务名].md`（任务清单）。
2. 每个原子任务必须包含：
   - 任务 ID 与描述
   - 输入/输出契约
   - 依赖关系（用 Mermaid 绘制依赖图）
   - 明确验收标准
   - 估算复杂度（控制在可单步高成功率范围内）
3. 按依赖关系排序，优先核心路径（MVP）。

**质量门禁**：
- 任务覆盖全部需求，无遗漏
- 每个任务原子化、可独立测试
- 依赖无循环，顺序清晰
- 用户确认拆分合理后再进入审批

## 阶段 4: Approve（审批阶段）
**目标**：人工把关，防止方向性错误。

**执行步骤**：
1. 汇总前三个阶段所有文档（ALIGNMENT + CONSENSUS + DESIGN + TASKS）。
2. 向用户呈现完整计划，突出风险点、决策点。
3. 执行检查清单：
   - 完整性、一致性、可行性、可测性、可控性
4. 记录用户反馈，只有用户明确回复“Approve”或“已确认”后，才能进入 Automate。

**质量门禁**：
- 必须有明确的批准记录
- 所有重大反馈已处理
- 禁止在未批准前生成代码

## 阶段 5: Automate（自动化执行阶段）
**目标**：严格按批准文档施工。

**执行步骤**：
1. 按 TASKS 清单中的依赖顺序逐个执行原子任务。
2. 每个子任务流程：
   - 检查前置条件
   - 按 DESIGN 文档编写代码（严格遵循项目代码风格、命名规范）
   - 编写单元测试
   - 运行验证
   - 更新文档
3. 代码要求：简洁、可读、复用现有组件、API Key 放入 .env 不提交。
4. 遇到不确定问题立即中断，记录在任务文档中并询问用户。
5. 每完成一个任务立即验证并记录。

**质量门禁**：
- 所有变更有文档依据（可追溯）
- 代码风格与项目一致
- 通过 lint 和基本测试

## 阶段 6: Assess（评估阶段）
**目标**：验证质量，不合格则迭代。

**执行步骤**：
1. 更新 `docs/任务名/ACCEPTANCE_[任务名].md`，逐条对照验收标准检查。
2. 执行整体验证：编译通过、测试通过、功能完整、与设计一致。
3. 质量评估维度：代码规范、可读性、测试覆盖、文档完整性、无新增技术债。
4. 生成 `docs/任务名/FINAL_[任务名].md`（总结报告）和 `docs/任务名/TODO_[任务名].md`（剩余事项清单）。
5. 如果未达标，返回对应阶段迭代；达标后询问用户 TODO 处理方式并提供指引。

**质量门禁**：
- 所有验收标准 100% 满足（或明确记录例外）
- 用户最终签收（Sign-off）
- 生成完整交付物

## 通用原则（全程强制）
- **文档驱动**：每个阶段必须先生成 Markdown 文档，放在 `docs/任务名/` 目录下。
- **严格顺序**：不允许跳阶段，Align 未完成禁止 Architect，以此类推。
- **人工介入点**：Approve 和 Assess 为强制 checkpoint。
- **输出风格**：使用中文文档（除代码外），Mermaid 图表辅助说明，语言专业、清晰、可追溯。
- **异常处理**：任何不确定立即暂停询问用户。
